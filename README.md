# qlport

Research code for **"Switching Costs as a Language-Design Artifact: Are Observability Query
Languages Inter-Translatable?"** (CS 681, Applications of Computability).

Main direction: **Datadog metrics queries → PromQL**: a company currently sending metrics to
Datadog wants to send them to Prometheus instead, and its dashboards and alerts must keep working.

## Layout

```
src/qlport/        the library: grammars, parser, IR, lowering, emitters, semantics
  grammars/        Lark grammars (LALR(1); a conflict-free table is the unambiguity proof)
  ir.py            typed series algebra (Select, Window, RangeFn, Agg, BinOp, Rollup)
  lower/           AST -> IR, one module per source language
  emit/            IR -> query text or Bottom(gap), one module per target language
  diagnostics.py   named semantic gaps; every ⊥ carries one
  semantics/       reference models: data model, ingestion maps, evaluators
  regular.py       regex <-> glob translation checked by DFA equivalence
  metrics.py       result distance d and coverage κ
  harness/         live dual-write + query harness (Prometheus, Datadog trial)
tests/             pytest; run before every notebook rerun
notebooks/         thin narrative layer, one per paper section (jupytext .py, percent format)
data/corpus/       collected dashboards and extracted queries
data/raw/          recorded API responses; append-only, never edited by hand
data/processed/    derived tables (regenerable)
paper/             the LaTeX paper; figures/ and tables/ are generated by notebooks
proposal/          frozen copy of the submitted proposal
scripts/           one-off fetchers (corpus download, etc.)
```

## Rules

1. Logic lives in `src/qlport` with tests; notebooks only import, run experiments and plot.
2. Every number in the paper comes from a file in `paper/figures` or `paper/tables`
   written by a notebook.
3. Live API calls go through `harness/` and are cached in `data/raw/`. Notebooks read the
   cache, so they still run after the Datadog trial ends.
4. Secrets go in `.env` (gitignored): `DD_API_KEY`, `DD_APP_KEY`, `DD_SITE`, `PROM_URL`.

## Commands

```
make install     # creates .venv, editable install, registers the "qlport" Jupyter kernel
make test        # pytest
make notebooks   # execute every notebook end to end (regenerates figures/tables)
make paper       # build paper/main.pdf
make all         # test -> notebooks -> paper
```
