# qlport

Research code for **"A Dashboard Query Does Not Say What It Means: Switching Costs in
Observability Query Translation"** (CS 681, Applications of Computability).

Main direction: **Datadog metrics queries → PromQL**: a company currently sending metrics to
Datadog wants to send them to Prometheus instead, and its dashboards and alerts must keep working.

## Layout

```
src/qlport/        the library: grammars, parser, IR, lowering, emitters, semantics
  grammars/        Lark grammars (LALR(1); a conflict-free table is the unambiguity proof)
  ir.py            typed series algebra (Select, Window, RangeFn, Agg, BinOp, Rollup)
  lower/           AST -> IR, one module per source language
  emit/            IR -> query text or Bottom(gap), one module per target language
  diagnostics.py   named semantic gaps; every ⊥ carries one
  semantics/       reference models: data model, ingestion maps, evaluators
  regular.py       regex <-> glob translation checked by DFA equivalence
  metrics.py       result distance d and coverage κ
  harness/         live dual-write + query harness (Prometheus, Datadog trial)
tests/             pytest; run before every notebook rerun
notebooks/         thin narrative layer, one per paper section (jupytext .py, percent format)
data/corpus/       collected dashboards and extracted queries
data/raw/          recorded API responses; append-only, never edited by hand
data/processed/    derived tables (regenerable)
paper/             the LaTeX paper; figures/ and tables/ are generated by notebooks
proposal/          frozen copy of the submitted proposal
scripts/           one-off fetchers (corpus download, etc.)
```

## Rules

1. Logic lives in `src/qlport` with tests; notebooks only import, run experiments and plot.
2. Every number in the paper comes from a file in `paper/figures` or `paper/tables`
   written by a notebook.
3. Live API calls go through `harness/` and are cached in `data/raw/`. Notebooks read the
   cache, so they still run after the Datadog trial ends.
4. Secrets go in `.env` (gitignored): `DD_API_KEY`, `DD_APP_KEY`, `DD_SITE`, `PROM_URL`.

## Commands

```
make install     # creates .venv, editable install, registers the "qlport" Jupyter kernel
make notebooks   # execute every notebook end to end (regenerates figures/tables)
make data        # the scripts that write the rest of data/processed/
make test        # pytest
make paper       # build paper/main.pdf and paper/main_full.pdf
make all         # install -> notebooks -> data -> test -> paper
```

On a fresh checkout run them in that order. Everything under `data/processed/` is derived
and gitignored, so a clone has none of it, and nine tests read files that `make
notebooks` and `make data` produce between them --- run out of order they fail by having
nothing to read rather than by disagreeing with anything. `make data` needs `docker` and
`node`, which is why it is not a dependency of `make test`: a machine without them can
still run the suite against data it already has.

Two steps reach the network and are therefore not in any target. `scripts/fetch_corpus.py`
downloads the corpus and writes `data/corpus/queries.jsonl`, which is committed;
`scripts/heldout_fetch.py` does the same for the held-out set in `data/heldout/`, taking
community dashboards past the rank the corpus stopped at and `integrations-core` at a
later commit. Both pin what they fetched in a manifest beside the queries, and neither
needs to run again to reproduce anything in the paper --- `make data` scores the committed
held-out queries with `scripts/heldout_eval.py` and cross-validates the committed corpus
with `scripts/heldout_split.py`. Re-running `heldout_fetch.py` replaces the held-out set
with a later one, which is a new experiment rather than a reproduction of this one.

`make paper` runs `pdflatex` three times, not twice. The table of contents has a length
of its own and that length moves every page number after it, so a two-pass build
typesets a contents page from the pass before it finished --- correct on disk, wrong in
the PDF. `test_the_build_converged` reads the warning LaTeX issues when that happens.
